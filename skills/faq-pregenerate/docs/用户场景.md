# 用户场景

按「谁 → 什么情况下 → 说什么 → 得到什么 → 注意什么」组织。每个场景都能照着跑一遍。

---

> ⚠️ 本技能尚未填写真实场景（`scenarios`），下面为**通用推导**，信息量有限。

## 场景一 · 发布日冲刺指挥官的日常用法

- **角色**：发布日冲刺指挥官
- **触发时机**：需要「FAQ 预生成」这件事有结果的时候
- **他会说**：`用 faq-pregenerate 帮我FAQ生成`
- **需要准备**：产品/服务说明
- **拿到什么**：FAQ 库（问题 / 应答 / 证据 / 风险）
- **容易踩的坑**：只写'优点类'问题（'你们为什么好'）而回避价格与缺点质疑，是最常见的失效原因

---

## 场景二 · 换成你自己的材料

同一句话，把材料换成你手头的真实数据即可：

```text
用 faq-pregenerate 处理下面这份材料：
<粘贴你的内容 / 贴文件路径>
```

**输入结构不要改**：字段名变了，脚本会读不到；缺字段时应当被明确告知缺什么，而不是猜。

| 字段 | 必填 | 说明 |
|---|---|---|
| 产品/服务说明 | ✅ | 缺失会导致输出不可用 |
| 目标受众顾虑 | ⬜ | 有则更好 |
| 历史被问最多的问题 | ⬜ | 有则更好 |
| 竞品被吐槽点 | ⬜ | 有则更好 |

## 场景三 · 边界情况（重要）

这几条写清楚做不到什么，比列一堆能力更有用：

- 不生成法律、医疗、投资类确定性承诺
